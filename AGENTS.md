# AGENTS.md — WINE.md Voice Lite

## Назначение

WINE.md Voice Lite — отдельный модуль WINE AI для сайта и виджета. Проект отвечает за загрузку и подготовку документов, закрытый RAG, benchmark-наборы, API и интерфейс виджета.

Основные рабочие контуры:

```text
site/widget request → API → knowledge retrieval → grounded response
admin upload → document parsing → chunks → embeddings → searchable knowledge
benchmark job → generated dataset → validation → review UI
```

Не выдумывай вина, винодельни, цены, наличие, награды, винтажи или факты, которых нет в источниках проекта.

## Перед работой

1. Прочитай `README.md` и `package.json`.
2. Определи, какой контур затрагивает задача: widget/UI, API, knowledge ingestion, embeddings, benchmark или database.
3. Загрузи только относящиеся к задаче код, документацию и тесты.
4. Прочитай `docs/agent-context/WORKFLOW_EFFICIENCY.md`.
5. Перед завершением проверь узкие тесты и только затем более широкий набор проверок, если он нужен.

## Обязательные правила

- Репозиторий не зависит от локальных соседних проектов и не импортирует файлы за своими границами.
- Виджет не должен ломать стили, навигацию, производительность или безопасность сайта, куда он встроен.
- Все ответы по винам и винодельням должны быть основаны на доступных источниках знаний.
- Изменения ingestion, chunking и embeddings должны быть идемпотентными и проверяемыми.
- Не создавай параллельный источник истины, если уже существует рабочий storage или service.
- Не печатай, не сохраняй и не коммить секреты, API-ключи, токены, production URL или пользовательские данные.
- Не меняй публичные API-контракты без явного требования задачи и проверки обратной совместимости.
- Не выполняй deploy, merge, production DB write, migration, prune, изменение Railway variables или доступов без отдельного явного разрешения.

## Работа и проверка

Делай минимальное изменение, устраняющее доказанную причину. Не смешивай исправление с посторонним рефакторингом, форматированием и переименованиями.

Правила экономии контекста, тестов и безопасных production-операций находятся в:

`docs/agent-context/WORKFLOW_EFFICIENCY.md`

Ключевые требования:

- одна узкая задача за этап;
- короткий план до изменения кода;
- только релевантные файлы;
- узкие тесты во время работы;
- полный suite перед commit, PR, merge или deploy, когда это оправдано;
- остановка после указанного checkpoint;
- destructive и production-операции только после отдельного разрешения.
