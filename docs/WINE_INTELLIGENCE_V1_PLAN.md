# WINE Intelligence v1

## Статус реализации

Constraint Engine v1, защищённый API проверки и вывод результатов в Answer Audit реализованы в ветке `feature/wine-intelligence-v1`. Тестовый прогон выявил слишком узкое ожидание `sourceText`; проверка исправлена, после чего запускается повторный полный CI.

## Цель

Построить поверх существующих Knowledge Graph, документов, Wine.md и веб-поиска прикладной интеллектуальный слой, который умеет:

- подбирать вина под вкус пользователя;
- строить маршруты с ограничениями по времени, бюджету и географии;
- сравнивать вина по стилю;
- объяснять гастропары;
- показывать происхождение каждого смыслового фрагмента ответа;
- отделять подтверждённые факты от выводов AI;
- проверять ограничения перед выдачей ответа;
- отправлять сомнительные выводы в админ-аудит.

## Что делаем сейчас

### Этап 1. Единый Answer Orchestrator

Создать слой, который последовательно опрашивает:

1. Knowledge Graph;
2. каталог Wine.md;
3. документы;
4. веб-поиск;
5. модель для экспертного вывода.

Каждый полученный фрагмент должен иметь происхождение, уровень доверия, дату актуальности и тип использования.

Критерий готовности: API возвращает чистый ответ, answerLayer, sources и provenanceSegments.

### Этап 2. Constraint Engine

Выделить и проверять ограничения пользователя:

- бюджет;
- даты;
- число виноделен;
- время возвращения;
- расстояние;
- стиль вина;
- обязательные и исключённые условия.

Критерий готовности: ответ не может выйти, если сам нарушает явное ограничение. Нарушение отображается в админ-аудите.

### Этап 3. Recommendation Engine

Добавить структурированные профили:

- вкусовой профиль вина;
- предпочтения пользователя;
- правила сравнения стилей;
- объяснимые гастропары;
- ранжирование кандидатов.

Критерий готовности: рекомендация содержит причины выбора, отличия, степень уверенности и источники характеристик.

### Этап 4. Route Planner

Добавить планирование маршрутов:

- точки старта и возврата;
- расстояния и последовательность;
- часы работы;
- длительность визита;
- питание;
- бюджет;
- контраст стилей между днями или остановками.

Критерий готовности: маршрут проходит автоматическую проверку бюджета, времени и логистики.

### Этап 5. Admin Quality Lab

Расширить `/admin/answer-audit.html`:

- показать каждый смысловой фрагмент ответа;
- показать источник, страницу, URL и дату актуальности;
- пометить AI inference;
- показать выполненные и нарушенные ограничения;
- дать оценку ответа: корректно, частично, неверно, сомнительно;
- сохранить результаты теста.

Критерий готовности: редактор может понять, почему появился каждый фрагмент ответа и где ошибка.

### Этап 6. Regression Benchmark

Создать постоянный набор тестов:

- вопросы по фактам;
- вопросы с конфликтующими источниками;
- гастропары;
- сравнение стилей;
- маршруты;
- бюджетные ограничения;
- актуальные данные;
- вопросы без ответа.

Критерий готовности: каждый deploy автоматически проверяет качество и не пропускает критические регрессии.

- Route Planner v1;
- Admin Quality Lab;

- правила приоритетов источников;
- журнал качества.

## Что зависит от внешних данных

- реальные цены и наличие Wine.md требуют API, JSON-фида или webhook со стороны Wine.md;
- точные часы работы, расписания и экскурсии требуют официальных источников или веб-поиска;
- полноценная геологистика требует координат виноделен и надёжного сервиса расстояний;
- экспертная точность рекомендаций растёт по мере наполнения графа проверенными характеристиками вин.

## Порядок реализации

1. Answer Orchestrator и provenance schema.
2. Constraint Engine.
3. Admin Quality Lab v2.
4. Recommendation Engine v1.
5. Route Planner v1.
6. Regression Benchmark.
7. Подключение Wine.md.
8. Расширение онтологии и редакторских инструментов.

## Правило выпуска

Каждый этап идёт отдельным набором тестов. До merge в main обязательны:

- unit tests;
- API smoke tests;
- проверка совместимости со старым виджетом;
- проверка PostgreSQL migration path;
- ручной прогон контрольных вопросов в Admin Quality Lab.
